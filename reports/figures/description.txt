Figure 1: File size by class. Both distributions are strongly right skewed. Most files are under about 500 KB, with a few reaching several MB. The AI class has slightly more mass around 1000 to 2000 KB, but the classes overlap too much for file size to be a reliable shortcut.
Figure 2: Height by class. Height behaves like width: both classes centre on about 500 to 1000 px and RealArt has the longer tail, to about 7000 px. The spread is very wide, so every image must be resized to one fixed shape, which makes the aspect ratio decision in 2.1 matter.
Figure 3: Width by class. Both classes peak between roughly 600 and 1200 px and overlap heavily. RealArt has more very small images and a longer tail out past 4000 px, up to about 8500 px. The overlap means width alone cannot separate the classes, so the model has to learn from the image content.
Figure 4: Random samples, AiArtData. The AI class is mostly stylised imagery: fantasy portraits, cartoon animals, illustrated landscapes and promotional banners. Some files are not clean generations. One is a screenshot with a face detection box drawn on a cat, and another is a banner with the words “AI-generated art” printed on it. A model could learn from that text rather than from how the image was made.
Figure 5: Random samples, RealArt. The “real” class is not only photographs. It also holds paintings, a Picasso, a palette of brushes and children’s drawings. A few images look polished enough to be AI to my eye, such as the colourful portrait with the earring and the sunrise lake. That suggests some label noise, which belongs in the error analysis later (2.6).
